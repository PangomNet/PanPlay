
0.1.1.0 Everlasting [Build 1030] (Prerelease development build, not for public use)
- Completed changes in this development build:
    - Fixed a net-error modal stability issue where repeated playback/network failures could leave the modal/backdrop in a broken state and force the user to reload the page.
    - The net-error modal now reuses a single Bootstrap modal instance instead of creating a new instance for every audio error, abort, or stalled event.
    - The net-error server-check interval is now stored and cleared safely. The previous code created intervalId inside showModalAndStartInterval(), but tried to stop it from closeModalAndStopInterval(), where that variable was not in scope.
    - The net-error modal now uses modal-dialog-scrollable to reduce the risk of broken page/backdrop scrolling when the error text becomes long.
    - Implemented the same core language logic used by other UI parts for the net-error reload button. The reload_player key is now available in all current PanPlay core language files.
    - The laut.fm extension keeps its localized net-error modal and server-status check.
    - The baseaudio extension now has its own net-error modal instead of falling back to the generic/laut.fm-oriented handler.
    - The baseaudio net-error handler performs a generic reachability check for the requested audio URL instead of expecting the laut.fm server_status JSON structure.
    - Local render checks confirmed that the laut.fm handler outputs the localized reload button, that the baseaudio handler is loaded for webstream mode, and that the old stopCheckInterval(intervalId) bug is no longer present in rendered HTML.
    - Implemented the first PanPlay CPM interpreter for baseaudio.
    - CPM now normalizes baseaudio URLs, reads local filter rules from data/cpm/local-filterlist.txt, and can combine them with the central CPM by CDN list.
    - CPM by CDN now downloads https://play.pangom.net/cpm/filterlist.txt, resolves supported !@import entries, and stores the merged cache in data/cpm/cdn-cache-filterlist.txt with metadata in data/cpm/cdn-cache-meta.json. Playback URLs are checked locally and are not sent to Pangom/PanPlay during normal CPM checks.
    - The CPM rule parser supports comments, [Adblock Plus] headers, exact URLs, domain rules such as ||example.com^, domain/path rules, simple wildcards, and @@ exception rules. Unsupported cosmetic filter syntax and ABP options are ignored for the first implementation.
    - When a baseaudio URL is blocked by CPM, PanPlay stops before rendering the player UI and shows the existing PanPlay Bluescreen with a 403 status and the matched rule source.
    - CPM Bluescreen content now uses the PanPlay language files instead of hardcoded English text. It links to https://play.pangom.net/cpm/ when CPM by CDN is active, and otherwise falls back to the instance operator website configured in storage.php.
    - Implemented the first connected settings surface for user/session URL parameters.
    - The settings dialog now exposes language and theme selection as URL/session parameter controls instead of requiring users to manually edit parameters.
    - The settings system now loads extension-specific option surfaces through the active extension's ext-options.php.
    - The laut.fm extension settings now expose URL toggles for schedule, station info, play-with display, track history, current-song window, live-by-name mode, and the global nolfmw feature-window switch.
    - The baseaudio extension settings now expose a direct webstream URL input that reloads the player with the updated URL parameter.
    - Settings are explicitly treated as user/session URL settings. They do not write server-side configuration and are not an admin panel.
    - Settings no longer reload the player immediately for every single option click. The dialog now collects changes in one form and applies them through a single footer button.
    - After applying settings, the player reloads with the new URL parameters and automatically opens the settings dialog again. The temporary settings=open helper parameter is removed from the visible URL after the modal has reopened.
    - Extension settings labels were moved into language files. French, Italian, Spanish, Dutch, Danish, Hindi, and Chinese now have translated settings labels instead of inheriting English placeholder text.
    - The settings modal markup was cleaned up so the form is the Bootstrap modal-content element and the modal body remains scrollable.
    - German settings strings and related visible core strings were corrected after mojibake was found in the language files.
    - The laut.fm "play with" wording now describes the actual feature more clearly as switching/opening the player somewhere else. German now uses "Player wechseln"; the other supported languages were adjusted with equivalent labels.
    - The laut.fm settings UI now reflects the global nolfmw feature-window override. If nolfmw is active, the individual feature-window switches are shown as disabled because they are ignored by the runtime until the global switch is turned off again.
    - The laut.fm runtime now accepts nolfmw=j as a legacy alias while continuing to use nolfmw=y as the current active value. The settings UI writes the current y/n form.
    - The lbn switch remains independent from nolfmw because it changes live-label behavior and is not one of the feature windows hidden by the global feature-window override.
    - The lbn switch was moved into its own playback-behavior section in the settings UI so it is no longer presented as a laut.fm feature window.
    - Added a default/reset button for laut.fm feature windows. It clears the global hide-all state and sets the individual feature-window switches back to visible before the user applies the settings.
    - Hindi and Chinese visible language names, settings descriptions, and About dialog texts were corrected where older mojibake strings were still rendered in the player.

0.1.0.1 Dandelion [Build 1029]
- Internal Git and repository structure:
    - The old Master-Changelog file is no longer treated as part of each release. It is obsolete and will no longer be maintained. Current development notes are kept in the changelog of the active release folder, on https://play.pangom.net/, and in the GitHub release notes. The Master-Changelog was created before PanPlay became a separate GitHub project and is no longer relevant for release packaging.
    - The old oOPlay base package has been moved to the Archive folder. Archive is kept as an old code and resource collection for historical reference and optional reuse, but it is not part of the active player files under Releases.
- Browser support:
    - The player compatibility check has been updated as part of the new browser support service at https://browser.pangom.net.
    - The 2026 browser support update raises the minimum technical requirements for Pangom services. Supported clients must provide modern Web APIs (ES2021+) and current security capabilities such as TLS 1.3. PanPlay now targets browser engines released around early 2021 or later. This means Chrome 86+, Firefox 86+, Edge 91+, Safari 14+, Vivaldi 5+, and Opera 71+. Internet Explorer and legacy Edge (EdgeHTML) are blocked server-side.
    - A global compatibility bypass parameter has been introduced. Adding lgc=on to the URL disables the server-side compatibility check for debugging and edge cases. This does not remove protocol-level requirements such as TLS support.
    - A forced compatibility test mode has been added. Adding lgc=netscape to the URL makes PanPlay treat the request as outdated even on a modern browser, so the compatibility error path can be tested.
    - PanPlay now routes compatibility failures through the existing PanPlay Bluescreen interface instead of delivering the full browser.pangom.net Tailwind interface to outdated browsers. The Bluescreen content uses PanPlay language files for every supported language and includes browser-service help links.
    - The Bluescreen frame text is now localized through the PanPlay language files as well. The displayed error code is generated from the actual Bluescreen status instead of being hardcoded as 500 Internal Server Error.
    - The Bluescreen function now safely falls back to 500 Internal Server Error when called without a valid status code or through an older two-argument call style.
- Central instance configuration:
    - Player identity, version information, hoster/legal references, and global behavior flags are now centralized in /data/storage.php.
    - engine/config.php is no longer loaded by the active player initialization path. Values that were previously provided by engine/config.php are now provided by storage.php.
    - storage.php is loaded at the beginning of engine/init.php so that Bluescreen paths, first-run state, hoster information, legal URLs, language behavior, and core attribution data are available before the player UI is rendered.
    - cfg_debug_mode is now applied during early initialization. When enabled, PanPlay shows PHP runtime and startup errors directly in the player output for local debugging. When disabled, direct PHP error output is hidden from the player interface.
    - about_extension_link now controls whether the active extension credit in the About dialog is rendered as an external link or as plain text. enable_extension_credits is now provided by storage.php as part of the active configuration.
    - The current compatibility aliases keep older runtime variable names available while the player is being migrated to the new storage.php structure.
- Core attribution integrity:
    - The PanPlay engine attribution shown in the About dialog is no longer stored as one editable text string. It is assembled from protected pp_pro_* core values.
    - A SHA-256 attribution hash is checked during initialization. The hash is based on the plain concatenation of pp_pro_engine_name, pp_pro_copyright, pp_pro_license, pp_pro_license_url, pp_pro_company, and pp_pro_company_url.
    - If these core attribution values are changed without updating the expected hash, PanPlay stops with a Bluescreen explaining that the instance is misconfigured. This is intended to catch broken or accidentally altered attribution data. It is not a copy-protection mechanism.
    - If the core attribution values are intentionally changed in a valid downstream build, the expected hash in storage.php must be regenerated from the same concatenated value order.
- Legal document handling:
    - Privacy and imprint links are now controlled by the storage.php legal source switches.
    - If pro_privacy_useremotesopurce is true, the About dialog links directly to pro_privacy_link. If it is false, the About dialog links to engine/legal/index.php?doc=privacy and the text is loaded from data/privacy.txt.
    - If pro_imprint_useremotesopurce is true, the About dialog links directly to pro_imprint_link. If it is false, the About dialog links to engine/legal/index.php?doc=imprint and the text is loaded from data/imprint.txt.
    - Local legal text files must contain plain text only. HTML is escaped before rendering in the legal document interface.
    - Existing public URL parameters are unchanged by this change.
- Language behavior:
    - cfg_default_lang is now used as the server fallback language. Language codes are normalized, so en-US maps to the existing en-us language file.
    - cfg_auto_lang_override can disable automatic browser language detection. When enabled, PanPlay uses cfg_default_lang unless a valid hl URL parameter is supplied.
    - The existing hl URL parameter continues to work and still has priority over automatic browser detection.
- Laut.fm extension:
    - Laut streams no longer ship separate placeholder covers. The station logo is used instead. The same approach is used for background imagery, so the old placeholder images are no longer delivered with the player files.
