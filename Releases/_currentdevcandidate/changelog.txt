0.1.1.0 Everlasting [Build 1030] (Development milestone, not for public use)
- Development target:
    - Everlasting starts as the next development cycle after the public 0.1.0.1 Dandelion Build 1029 release.
    - Everlasting was originally considered as 0.1.0.2, but the planned scope includes new feature systems, UI changes, CPM, metadata expansion, and theming architecture work. It is therefore treated as a minor feature release instead of a small patch update.
    - The development time is expected to include more intermediate development builds than the last release cycle, starting with Build 1030. Build 1030 begins with the implementation of CPM.
    - This section is a working plan for the next days and weeks. Items listed here are not release-complete yet and should be checked off, rewritten, or moved into final release notes as they are implemented.
- Stability and known bugs:
    - Investigate a known offline modal rendering bug.
    - In some connection-loss situations, the "You are offline!" connection error window appears but is rendered incorrectly.
    - When the bug occurs, the modal backdrop may no longer be scrollable and the offline window may not close properly.
    - This must be fixed before larger UI features are layered on top of the current modal/error handling.
- GitHub issue planning:
    - The open GitHub issues have been reviewed for the Everlasting development cycle.
    - Issue #6, "Graphical Bugs (Backdrop and some FontAwesome-Icons) on Safari", should be handled early because it is related to the same stability/UI layer as the known offline modal backdrop problem.
    - Issue #7, "option to share this player on Facebook, Instagram, etc.", is already part of the planned share feature and should be implemented once the settings and parameter handling are stable enough.
    - Issue #5, "Laut.fm - General ICY discussion", should be considered during the metadata work. The goal is not to force direct ICY extraction in the browser, but to improve the existing API-based metadata path for UI, Media Session, and Cast output.
    - Issue #4, "English (and other languages) support and translation support", has already been partly addressed by the language system and Bluescreen localization work. Remaining language gaps should be cleaned up during Build 1030 when touched by new core features.
    - Issue #12, "Related Stations-Box", should remain parked for now. It may become useful after the settings/parameter surface and laut.fm UI structure are clearer.
    - Issue #1, "Implementation of Three.js Visualizations", should remain a future feature request. It is interesting, but too large and separate from the current CPM/settings/metadata focus of Everlasting.
    - For Build 1030, the priority order from the issue list is therefore: fix Safari/backdrop-related UI bugs first, then continue language cleanup where needed, then implement share support, and only then revisit larger laut.fm UI expansion ideas.
- CPM and content protection:
    - Implement PanPlay CPM (Content Protection Mechanism) as the next major background feature.
    - CPM is intended to apply to the baseaudio extension only. Laut.fm streams are not the target of CPM because they already use the laut.fm platform/API flow.
    - Implement local CPM checks for baseaudio URLs so that URLs known or flagged as copyright-infringing can be blocked before playback.
    - Implement CPM by CDN as an optional mode. When enabled, PanPlay should use a central Pangom/PanPlay-hosted list instead of only a local server-side list.
    - CPM by CDN must be treated as privacy-relevant because the checked playback URL may be transmitted to Pangom/PanPlay infrastructure. The documentation and configuration comments must make this clear.
    - The existing storage.php flags cfg_panplay_cpm and cfg_panplay_cpm_by_cdn are the starting point for this work.
- Settings interface:
    - Continue building the settings surface so users do not need to manually search for URL parameters in the DOM or documentation.
    - The existing extension settings groundwork should be connected so each active extension can provide its own settings controls.
    - Extension parameters should be editable through the settings dialog and should generate or apply the corresponding player URL/state.
    - General PanPlay parameters should also be exposed in the settings UI, including commonly used values such as theme selection.
    - The goal is that a user can change settings through the interface, receive the updated player view, and understand which parameter/state was changed.
- Theme and design system work:
    - Update the default Bootstrap-based theme further toward the Mica-inspired look that is already used in the current PanPlay UI.
    - Improve small visual details such as subtle borders, depth, hover feedback, and shadow/light effects that react more like Windows 10 UWP-style transparent interfaces.
    - Separate PanPlay's base interface rules from the theme-specific rules more clearly.
    - Long-term goal: themes should not be forced to use Bootstrap as their base. A theme should eventually be able to use another foundation such as W3.CSS, Material, Tailwind, or a custom UI system.
    - This is expected to be a larger architectural topic because the interface, Bootstrap markup, player components, and theme files are currently still closely connected.
    - The long-term theming goal is to allow a theme to reshape the interface on a level closer to old Windows Media Player skins, not only recolor the existing interface.
- Laut.fm schedule and metadata windows:
    - Make shows listed in the laut.fm schedule clickable.
    - Clicking a schedule entry should open a dedicated detail window for that show.
    - The show detail window should include the available show data from the laut.fm show/schedule endpoints.
    - A long-missing station/show description should finally be included where the API provides one.
    - The current playback / now playing window should also be revised and expanded with additional song and broadcast metadata.
    - Both the show detail window and the current playback window must only display values that are actually present in the laut.fm API response, are not empty, and contain logically useful information.
    - The implementation should review the full set of values exposed by the relevant laut.fm endpoints for shows/schedule data and songs/current-song data, instead of only using the few fields PanPlay already displays today.
- Laut.fm rich content tab:
    - Extend the remote-source concept already used for legal documents to the laut.fm playback screen.
    - Add a tab next to the album cover/station view that can show station-provided rich content.
    - For security and predictability, the rich content source must be derived from a configured/known station website, not from arbitrary user input.
    - Example: if a laut.fm station exposes its official website through the API as geilemukke.de, PanPlay should only attempt to load content from a controlled path such as geilemukke.de/playercontent.md.
    - The station operator must prepare/configure the content intentionally. PanPlay should not scrape random station pages.
    - The content format should be limited to Markdown so station operators can maintain it easily while PanPlay avoids loading arbitrary HTML, scripts, crypto links, or full embedded websites into the player.
    - The Markdown renderer/sanitizer must be chosen carefully. The result should be useful rich content, but still safe and limited in scope.
- Share feature:
    - Add a parameter that controls whether a share icon appears in the top-right menu.
    - When enabled, the share UI should allow the current player page/link to be shared through common social media and sharing targets.
    - The feature should preserve the current playback URL parameters so shared links reproduce the intended player state.
    - Browser-native sharing can be considered where available, with simple fallback links for desktop browsers that do not support it.
- Baseaudio metadata and Media Session work:
    - Finish more of the long-standing baseaudio extension work.
    - Use getID3 in baseaudio to attempt metadata extraction from direct audio files entered by the user.
    - Extracted metadata should be used in the player UI where possible.
    - Extracted metadata should also be passed to Chromecast metadata, comparable to how the laut.fm extension already provides metadata through the laut.fm API.
    - Extracted metadata should be passed to the browser Media Session API so operating systems and browser surfaces can show title/artist/album artwork where supported.
    - This should bring baseaudio closer to the feature quality of the laut.fm module, while still respecting that direct files and streams may not always expose useful metadata.
- Rough work order:
    - First, fix known stability issues and small broken surfaces, especially the offline connection error modal/backdrop bug. The player should not trap users in a broken error window before new UI features are added.
    - Next, clean up and connect small configuration/UI foundations that are already partly present, including extension settings groundwork and general parameter handling.
    - Then define the CPM behavior and data flow for local CPM and CPM by CDN, including what is checked, where lists live, and what error path is shown when content is blocked.
    - After the CPM foundation is clear, implement the first CPM path for baseaudio and document its privacy implications when CPM by CDN is enabled.
    - Then improve baseaudio metadata handling with getID3 and connect the results to UI, Chromecast, and Media Session output.
    - In parallel or after that, expand the laut.fm schedule/show detail windows and the current playback metadata window based on all useful fields available from the laut.fm API.
    - Then prototype the laut.fm rich content tab with strict Markdown loading and sanitization rules.
    - Add the share parameter and share menu once the settings/parameter handling is stable enough to expose it cleanly.
    - Treat theme architecture as a larger ongoing track. Small Mica polish can happen during Build 1030, while full theme-base independence will likely need multiple iterations and should not block smaller bugfixes.


0.1.0.1 Dandelion [Build 1029]
- Internal Git and repository structure:
    - The old Master-Changelog file is no longer treated as part of each release. It is obsolete and will no longer be maintained. Current development notes are kept in the changelog of the active release folder, on https://play.pangom.net/, and in the GitHub release notes. The Master-Changelog was created before PanPlay became a separate GitHub project and is no longer relevant for release packaging.
    - The old oOPlay base package has been moved to the Archive folder. Archive is kept as an old code and resource collection for historical reference and optional reuse, but it is not part of the active player files under Releases.
- Browser support:
    - The player compatibility check has been updated as part of the new browser support service at https://browser.pangom.net.
    - The 2026 browser support update raises the minimum technical requirements for Pangom services. Supported clients must provide modern Web APIs (ES2021+) and current security capabilities such as TLS 1.3. PanPlay now targets browser engines released around early 2021 or later. This means Chrome 86+, Firefox 86+, Edge 91+, Safari 14+, Vivaldi 5+, and Opera 71+. Internet Explorer and legacy Edge (EdgeHTML) are blocked server-side.
    - A global compatibility bypass parameter has been introduced. Adding lgc=on to the URL disables the server-side compatibility check for debugging and edge cases. This does not remove protocol-level requirements such as TLS support.
    - A forced compatibility test mode has been added. Adding lgc=netscape to the URL makes PanPlay treat the request as outdated even on a modern browser, so the compatibility error path can be tested.
    - PanPlay now routes compatibility failures through the existing PanPlay Bluescreen interface instead of delivering the full browser.pangom.net Tailwind interface to outdated browsers. The Bluescreen content uses PanPlay language files for every supported language and includes browser-service help links.
    - The Bluescreen frame text is now localized through the PanPlay language files as well. The displayed error code is generated from the actual Bluescreen status instead of being hardcoded as 500 Internal Server Error.
    - The Bluescreen function now safely falls back to 500 Internal Server Error when called without a valid status code or through an older two-argument call style.
- Central instance configuration:
    - Player identity, version information, hoster/legal references, and global behavior flags are now centralized in /data/storage.php.
    - engine/config.php is no longer loaded by the active player initialization path. Values that were previously provided by engine/config.php are now provided by storage.php.
    - storage.php is loaded at the beginning of engine/init.php so that Bluescreen paths, first-run state, hoster information, legal URLs, language behavior, and core attribution data are available before the player UI is rendered.
    - cfg_debug_mode is now applied during early initialization. When enabled, PanPlay shows PHP runtime and startup errors directly in the player output for local debugging. When disabled, direct PHP error output is hidden from the player interface.
    - about_extension_link now controls whether the active extension credit in the About dialog is rendered as an external link or as plain text. enable_extension_credits is now provided by storage.php as part of the active configuration.
    - The current compatibility aliases keep older runtime variable names available while the player is being migrated to the new storage.php structure.
- Core attribution integrity:
    - The PanPlay engine attribution shown in the About dialog is no longer stored as one editable text string. It is assembled from protected pp_pro_* core values.
    - A SHA-256 attribution hash is checked during initialization. The hash is based on the plain concatenation of pp_pro_engine_name, pp_pro_copyright, pp_pro_license, pp_pro_license_url, pp_pro_company, and pp_pro_company_url.
    - If these core attribution values are changed without updating the expected hash, PanPlay stops with a Bluescreen explaining that the instance is misconfigured. This is intended to catch broken or accidentally altered attribution data. It is not a copy-protection mechanism.
    - If the core attribution values are intentionally changed in a valid downstream build, the expected hash in storage.php must be regenerated from the same concatenated value order.
- Legal document handling:
    - Privacy and imprint links are now controlled by the storage.php legal source switches.
    - If pro_privacy_useremotesopurce is true, the About dialog links directly to pro_privacy_link. If it is false, the About dialog links to engine/legal/index.php?doc=privacy and the text is loaded from data/privacy.txt.
    - If pro_imprint_useremotesopurce is true, the About dialog links directly to pro_imprint_link. If it is false, the About dialog links to engine/legal/index.php?doc=imprint and the text is loaded from data/imprint.txt.
    - Local legal text files must contain plain text only. HTML is escaped before rendering in the legal document interface.
    - Existing public URL parameters are unchanged by this change.
- Language behavior:
    - cfg_default_lang is now used as the server fallback language. Language codes are normalized, so en-US maps to the existing en-us language file.
    - cfg_auto_lang_override can disable automatic browser language detection. When enabled, PanPlay uses cfg_default_lang unless a valid hl URL parameter is supplied.
    - The existing hl URL parameter continues to work and still has priority over automatic browser detection.
- Laut.fm extension:
    - Laut streams no longer ship separate placeholder covers. The station logo is used instead. The same approach is used for background imagery, so the old placeholder images are no longer delivered with the player files.
